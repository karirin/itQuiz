# 苦手克服コース

ITパスポート向けの初期版。Debug（開発者モード）でのみ、ホームとITパスポートで誤答があったクイズ結果から開く。Release（App Store向け）では入口を表示しない。

## 共通の「苦手克服」画面

テーマの練習・おさらいの問題演習は、問題の復習と同じ `ReviewExerciseContent` を使う。時間帯に応じた庭園の背景、白ひげのモンスター、問題・選択肢、出題数の進捗、問題の長さに応じた30〜60秒のタイマー、解説表示を共通化する。設定は学習モードと同じ `ModalView`、回答後の解説は `ModalExplanationView` を使い、解説の表示設定も共有する。「わからない」と時間切れは表示設定によらず解説を表示し、未習得として扱う。設定の「あとで続ける」から退出できる。テーマの進捗・無料枠・途中再開はコース側で管理する。

ホーム・学習モード・クイズ結果の入口は、同じ苦手克服ホームへ進む。問題の解き直し予定、今日のテーマ確認、苦手分野、テーマの説明と類題、克服図鑑をまとめて表示する。ホームの旧スケジュール復習ボタンは重複表示しない。既存の「今日の3問」と無料の保存済み誤答復習は引き続き利用できる。

- 解き直しは翌日・正解から3日後・正解から7日後、テーマ確認は練習の翌日・確認の正解から3日後という既存の間隔を維持する。
- 復習する問題に対応テーマがある場合は、その問題から説明・類題へ進める。未対応の問題を単語だけで分類しない。
- 克服図鑑には「克服した問題」と「克服したテーマ」を分けて記録し、テーマの説明も読み返せる。
- 通信が必要な解き直し予定を読めない場合も、端末に保存されたテーマの練習と成果を表示する。
- 問題とテーマの保存形式・無料テーマ・途中セッション・克服判定は維持する。今回は画面と導線を統合し、コースの回答で通常復習の進捗や報酬を更新しない。

`-WeaknessCoursePreview` は共通画面のサンプル予定・克服図鑑と、同期無効のコース状態を表示する。サンプル問題の通常復習は開始しない。`-CoursePremiumPreview` を追加すると加入状態で確認できる。

## 無料とプレミアムの利用範囲

- 問題の復習は、無料で1日5問。ホームの今日の復習・ITの誤答一覧・苦手克服ホームで枠を共有し、回答済みの問題を同日に再出題しない。正解・不正解・「わからない」・時間切れを回答として数える。未回答のまま退出した場合は消費しない。
- `ReviewAccessPolicy` が回答直前にも判定する。画面の再表示・途中再開・加入終了によって当日の回数はリセットしない。端末のローカル日付が変わると5問に回復する。旧ホーム復習の当日回答も引き継ぐ。無料枠は端末内のユーザー別保存で、複数端末を横断するサーバー側の回数制限ではない。
- プレミアムは問題数の制限なく利用でき、苦手分野を選ぶ集中特訓も利用できる。予定付きの復習は、期限が来た問題を出題する。通常の誤答一覧では保存された問題を解き直せる。
- テーマ練習は別枠。選択済み1テーマの説明・練習・後日の確認・再挑戦は無料、全10テーマはプレミアム。コースの回答で問題復習の5問枠を消費しない。
- 新しい誤答の復習予定は加入状態によらず `LocalReviewScheduleStore` に保存する。翌日・正解から3日後・正解から7日後に確認し、克服した記録も端末に残す。旧誤答を取り込む際には既存のクラウドの段階を引き継ぎ、より新しい端末の回答を古い通信結果で戻さない。
- 問題の復習予定・苦手一覧・克服図鑑は無料でも閲覧できる。予定の読み込みや無料枠の表示では、無料テーマを自動選択しない。
- プレミアムの復習結果と既存クラウドの問題に対する回答はオンライン時に従来の復習保存先にも反映する。無料の新規記録は端末に保存される。

`sh Scripts/test-review-access.sh` で、入口間の共有、上限、日付・アカウント境界、再開、加入・加入終了、旧データ移行、無料ユーザーの予定・克服記録を検証する。

## 学習と課金の仕様

- 10テーマ。説明、3問の練習、後日の2問の確認を提供する。既存問題集から関連問題を選び、手作業で用意した50問を不足時や問題の切り替えに使う。実行時のAI生成・外部生成APIは使わない。
- テーマはRAMとROM、暗号、デジタル署名、DNS、IPアドレス、バックアップ、フィッシング、多要素認証、損益分岐点、PDCA。
- 4つのITパスポート問題集（844問、同一内容の重複を除くと841問）を `ITPassportQuestionBank` に共通化。問題文・選択肢・正解から作成時に求めたSHA-256の先頭24桁を固定IDとして保持する。並び順を変えてもIDは変わらない。通常画面・学習分析も同じ静的データを使う。
- `CourseQuestionIndex.tags` は内容を確認した28問と10テーマの対応表。誤答の問題文・選択肢・正解が一致すると固定IDへ解決する。既存の23件の `sourcePrompts` と `.sourceN` IDも互換用に残す。未分類の問題を単語だけで分類しない。全841問がコース対応という意味ではない。
- 実際の誤答があるときは、導入画面で元問題・保存済みの選択回答・正解・既存解説を表示し、その元問題と同テーマの別の2問を練習する。誤答がないテーマも任意の練習として開始できる。
- 関連候補はテーマ別の索引から取り出し、未出題、最終出題日時が古い順で選ぶ。同条件では既存問題を優先し、用意済み問題で補う。同じ問題文を1セッションに重複させない。確認では元の誤答を除き、2回目の確認も最近出した問題に偏らないようにする。途中再開は保存したセッションの問題を維持する。
- 問題ごとの履歴はID・最終出題日時・正解数・不正解数。通常誤答で不正解を記録し、コース完了時に出題履歴と回答結果を確定する。途中回答は端末内のセッションに保存する。
- 練習の全問正解 → 翌日の同時刻以降に確認 → 全問正解 → さらに3日後に確認 → 全問正解でクリア。
- 不正解・「わからない」を含むセッションは練習に戻る。解説の表示がオンのときは「次の問題へ」を押すまで表示する。オフのときは回答保存後に自動で次へ進む。「わからない」と時間切れの解説は必ず表示する。
- 過去の誤答の取り込みは進行中のコースを戻さない。通常演習で新たに間違えた場合は、そのテーマを練習に戻す。
- 無料は最初に開始した1テーマ。後日の確認・再練習も同じテーマなら無料。加入者は全10テーマ。加入終了後も選択済みの無料テーマと記録を維持する。
- 購入画面では選んだテーマ名を表示し、既存のStoreKit商品・価格・オファー適格性・購入処理を利用する。新しい商品は作らない。
- 既存の誤答復習とコースの進捗は独立。誤答一覧から正解済み問題が削除されてもコースの確認予定は残る。

## 保存と同期

`WeaknessCourse.swift` はFoundationのみで動くモデルと状態遷移。`WeaknessCourseStore.swift` が端末保存・Firebase同期・Analyticsを担当する。

- ローカル：`weaknessCourses.v1.{userID}`。途中の回答・解説表示位置・無料テーマ・進捗を保存する。
- クラウド：`users/{uid}/weaknessCoursesV1`。テーマ別進捗・小さなID別履歴・無料テーマ・取り込み済みIDを保存する。元問題は同じ版が問題集にあれば `sourceQuestionID` のみ送信し、受信時に端末の問題集から復元する。旧版や独自の保存済み解説は全文のスナップショットを保持し、既存形式も読み込める。途中セッションは端末内だけに保存する。
- 認証中のUIDと一致するときだけ同期を試みる。アカウント切替で端末内の状態・接続監視を切り替え、古い非同期応答を捨てる。
- 初回・再接続・バックグラウンドからの復帰時に進捗を読む。過去の誤答の取り込みは、リモートの既存進捗を読んだ後に行う。未接続中の取り込み待ちは固定IDで重複を除く。
- 通常の誤答は端末に即保存し、クイズ完了・画面退出・バックグラウンド移行時にまとめて同期する。コースの開始（無料テーマ確定を含む）・完了時も同期する。途中の回答ごとには通信しない。
- 最後に成功したクラウド状態との差分を作り、変更のある `progress/{topicID}`、`freeClaim`、`importedSourceIDs` だけをトランザクションで送る。変更なしなら書き込まない。各テーマでは更新日時を比較し、他テーマを読み書きしない。無料テーマは先の選択を採用する。送信中の新しい変更や失敗した変更は未同期として残す。
- オフラインでは端末内で継続し、再接続時に同期する。同期失敗は画面に表示し、端末内の進捗を残す。
- Firebaseが空の辞書・配列を削除する場合をデコード時に扱う。
- 同時に同じテーマを進めた場合は更新日時が新しい進捗を採用する。端末時計の差が大きい場合の厳密な順序保証はない。

2026-10-04の読み取り確認では既存Realtime Databaseのルートが `.read: true` / `.write: true` だった。この変更では本番ルールを変更していない。上位で許可した権限は子のルールで取り消せないため、認証ユーザー本人だけに進捗を制限するには、既存機能全体の必要な権限を確認してルートから見直す必要がある。

## 計測

Releaseビルドで以下を送信する。Debugのプレビューは送信しない。

- `course_home_view`：一覧の表示
- `course_trial_start`：無料テーマの初回選択
- `course_session_start`：練習／確認の開始
- `course_session_complete`：完了、正解数、出題数、全問正解の有無
- `course_mastered` / `course_trial_complete`：日を空けた確認のクリア
- `course_upgrade_tap`：テーマから購入画面への遷移
- 既存の `paywall_view` / `purchase_success` 等に `source=weakness_course`、`course_topic_id`、`course_remaining_count` を追加

`purchase_success` は無料トライアル開始を含むため、有料更新率と混同しない。テーマ再克服によるイベントの再送があり得るため、無料体験完了率はユーザー単位で集計する。

## 検証

`sh Scripts/test-weakness-courses.sh` で状態遷移、途中再開、無料枠、加入終了、履歴に応じた選択、旧データ移行、IDによる復元、同期差分を検証する。844問の問題文・選択肢・正解・解説・順序は、共通化前のデータのダイジェストと比較する。IDと23件の互換対応も検証する。

`sh Scripts/test-weakness-courses.sh --benchmark` は最適化したSwiftをMacで実行する。2026-10-04の確認では、索引の初期化10.808ms、10,000回の関連問題選択で平均0.0315ms。10テーマに履歴を付けたサンプルは全文14,400B、ID形式7,867B、変更したDNSテーマだけなら775Bだった。iPhoneの画面描画・通信時間・Firebaseプロトコルの転送量は含まない。実機の操作や複数端末のFirebase同期は未検証。

Debug起動引数 `-WeaknessCoursePreview` で無料ユーザーの画面を、追加引数 `-CoursePremiumPreview` で加入ユーザーの画面を確認できる。独立したUserDefaultsを使い、コースのFirebase書き込みとAnalytics送信は行わない。

## テーマを増やすとき

テーマID・練習問題ID・確認問題IDは変更しない。`sourcePrompts` は末尾へ追加する（位置が元問題IDの一部）。文言変更前の問題との対応を残す場合は旧文言も維持する。

既存の問題とテーマの関連を確認して `CourseQuestionIndex.tags` に固定IDを追加する。索引と候補は自動で構築される。公開済みIDを削除する場合は復元用の旧データを残す。テーマの説明と正解・解説の一致を確認し、出題数を変更するときはUIとテストも更新する。
