# ストーリーモード

ホームの「ストーリーモード」から第1章「はじまりの森」を開けます。38地点の分岐マップ、宝箱、クイズ戦闘、古代の鍵、ボス、章クリアを実装しています。第3章以降は世界地図に今後の追加予定として表示します。

第1章をクリアすると、港町のイベントまたは世界地図から第2章「潮風の群島 ― 届かなかった返事」を始められます。12場面の会話と3回のクイズ戦闘で進みます。会話の途中ページ、戦闘の問題・回答・HP、章クリアは第1章と分けてアカウント別に端末保存します。右上の地図ボタンから読了した場面を読み返せます。第2章の進行ルールは `sh Scripts/test-chapter-two.sh` で検証できます。

村の西側、森の東側、滝の奥、港を望む丘に寄り道を追加しました。新しい宝箱とモンスターには個別の報酬があり、中間地点はすべて通過する小径として扱います。地点の番号と取得済み報酬は維持しているため、保存済みの冒険も続けられます。同じ道に直通ルートと途中の地点を通るルートが並ぶ7区間は、途中の地点を順番に通る一本道へ整理しました。既存のセーブで未探索だった地点は、そのまま探索・戦闘できます。

ホームの「絵本の森を冒険する」は、生成画像を背景にした別画面です。通常版と進行を共有し、表示上の世界を縦横3倍（面積9倍）に広げています。背景はヘッダーとフッターの背後まで画面いっぱいに広がります。隠れた部分は拡大してドラッグで見られます。ピンチ、＋／−、画面に広げる操作、現在地への復帰に対応します。画像の差し替え手順とChatGPT用プロンプトは [StoryWorldBackgroundPrompt.md](StoryWorldBackgroundPrompt.md) にあります。

画像版は、上部の「戻る・エリア名・メニュー」と下部の行動ボタンだけを常時表示します。クエスト、探索数、HP、所持コイン、もちもの、世界地図、ズーム操作は右上の「…」から開きます。地点名は選択中と現在地だけ表示し、他の地点もタップやVoiceOverで選択できます。戦闘再開ボタンには選択先ではなく中断中の敵の名前を表示します。

地図は2本指のピンチで拡大・縮小できます。iOS 17以降では指で挟んだ位置を中心にズームし、iOS 16では中央を基準にズームします。ドラッグとピンチは同じ操作状態で処理し、終了時に位置を一度だけ確定します。画像の画質に合わせた拡大上限と、画面に余白を出さない縮小下限を使います。Xcode 26のSimulatorでは、Optionキーを押しながら地図をドラッグしてピンチを再現できます（[Appleの操作ガイド](https://developer.apple.com/library/archive/documentation/IDEs/Conceptual/iOS_Simulator_Guide/InteractingwithiOSandwatchOS/InteractingwithiOSandwatchOS.html)）。

## 構成

- `AdventureWorld.swift`: 地点、経路、報酬、出題コースの定義。
- `AdventureProgress.swift`: 移動・戦闘・取得済み報酬のルールと、アカウント別の端末保存。
- `AdventureStore.swift`: 画面の状態、移動アニメーション、既存の問題集・ミッション・復習・コイン報酬との接続。
- `AdventureArtwork.swift` / `AdventureMapView.swift`: Canvasによる地形とイラスト、アバターのコマ、ドラッグ・ピンチ操作。
- `AdventureMapGeometry.swift`: 広域マップの表示座標、画面を覆う最低倍率、ズームとドラッグ範囲。保存データの座標・地点IDには影響しません。
- `AdventureImageBackground.swift`: 背景画像の設定、画面の描画領域への直接描画、画像版のホーム入口。採用した画像はAssetsの `StoryForestWorldPreviewIllustration`。背景素材は1枚で、端の地点へ移動した際にヘッダー・フッターの背後にできる隙間は同じ画像の端を延長して埋めます。HUDの背景は透明です。

画像版の拡大上限は実際の素材解像度と画素密度に合わせます。画質対策と差し替え条件は [StoryMapImageQuality.md](StoryMapImageQuality.md) を参照してください。
- `StoryAdventureView.swift` / `AdventureEventSheet.swift`: ホームの入口、探索画面、イベント、クイズ、もちもの、世界地図。

## 会話による物語

初回のマップ表示時に「小さな旅立ち」が全画面で開きます。森の入口、モススライム、古い祠、森の主、港町への到着時にも、各場面の会話が初回だけ入ります。背景と選択中のおともを表示し、セリフまたは「つづきを読む」をタップして進めます。前のセリフへの移動とスキップに対応しています。

「冒険メニュー → 旅の物語」から到達済みの場面を読み返せます。通常のストーリーマップでは上部の本のボタンからも開けます。再生しても場所・クリア状況・コインは変わりません。会話が終わると、その場所の探索・戦闘画面へ続きます。読み返しの場合は一覧へ戻ります。

台本と場面の解放条件は `AdventureStory.swift`、画面は `AdventureDialogueView.swift` です。会話の既読状態と途中のページは既存のアカウント別セーブへ保存します。新しい保存項目は任意項目のため、以前の進行・戦闘データも読み込めます。中断中の戦闘がある場合、会話は戦闘より優先されません。

Debug起動引数 `-StoryDialoguePreview` は、会話確認用の独立したアカウント・保存領域で起動します。通常プレイと従来のマッププレビューのセーブには影響しません。

## 戦闘終了時の広告

第1章・第2章とも、勝利または敗北した最後の問題の解説を閉じた時点で、インタースティシャル広告を最大1回表示します。広告を閉じてから結果・報酬や次の物語へ進みます。戦闘中に事前読み込みし、プレミアム、購入状態の確認前、通信なし、広告の準備が未完了の場合は待たずに先へ進みます。中断・再開や各問題の間では表示しません。

表示判定と計測は学習モードの `InterstitialOpportunityCoordinator` を共用し、`story_adventure_chapter01` / `story_adventure_chapter02` で記録します。プレビューでは広告・広告計測を実行しません。Debugビルドで使う全画面広告はAdMobのテスト広告です。

## 保存と報酬

進行はUserDefaultsにアカウント別に保存します。戦闘中の問題・選択済み回答・残りHPも保存するため、中断後に再開できます。保存データが不正な場合は上書きせず読み込みエラーを表示します。進行状況の端末間同期は含みません。

モンスター戦で敗北すると、到着時に通った直前の1コマへ戻ります。村への自動帰還やHPの自動回復はありません。HPが0の状態も保存され、所持している回復薬は手動で使用できます。

村へ戻ったり、村のイベントを開いたりしてもHPは回復しません。「休んでHPを全回復」を選ぶと、現在の最大HPまで回復します。

コインは既存の `AuthManager.grantRewardBundle` に、章と地点を組み合わせた固定の冪等キーを渡します。成功するまで未受取の記録を残し、通信復帰・画面表示・手動操作で再試行します。コインは共通の所持金に加算されます。第1章では6個の宝箱から回復薬を入手でき、古代の鍵とともに冒険内の持ち物です。

通常プレイではITパスポート・基本情報・応用情報の既存問題を使用します。回答はミッションに反映し、不正解は既存の端末内復習リストに保存します。各戦闘で抽出した問題は保存データに含め、再開時に問題順が変わることを防ぎます。

## レベル・オトモと戦闘ステータス

最大HPは `100 + (レベル - 1) × 10 + 選択中のオトモのhealth`、攻撃力は `20 + (レベル - 1) × 2 + オトモのattack` です。レベルとオトモは同じユーザーデータから読み込み、読み込みが完了してから新しい戦闘を開始します。未選択の場合はレベルの基礎値のみを使います。

戦闘外の変更では減っているHP量を維持し、HPが0のプレイヤーは装備変更では復活しません。戦闘中はプレイヤーと敵のステータスを固定して保存します。旧セーブの中断中の戦闘は旧仕様（攻撃30、被ダメージ20、敵HP60／ボス90）で再開し、戦闘後に新しいステータスを反映します。回復薬は最大HPの50％（端数切り上げ）を回復し、戦闘中は使えません。

| モンスター | HP | 攻撃 |
|---|---:|---:|
| モススライム・つる草スライム | 180 | 35 |
| 葉陰の番人 | 240 | 40 |
| リーフガード | 270 | 40 |
| 木漏れ日の守り手 | 300 | 45 |
| 風見の番人 | 360 | 50 |
| 霧のモススライム | 390 | 50 |
| 谷風の守り手 | 420 | 55 |
| 雲海の番人 | 450 | 55 |
| 森の主 | 1000 | 80 |

## 検証

アプリのソースディレクトリで次を実行します。

```sh
sh Scripts/test-story-adventure.sh
python3 Scripts/test-story-interstitial.py
```

移動制限、分岐、取得の重複防止、回答の二重処理防止、戦闘の再開、鍵、敗北時の復帰、章クリア、保存の分離、不正データの保護を検証します。テストは一時領域で実行し、Firebaseには接続しません。

`Tests/AdventureMapPinchUITests.swift` は、インストール済みのDebugアプリをプレビューモードで開き、実際の2本指イベントで拡大・縮小・連続ピンチ・地点選択を検証します。アプリ本体のビルド対象には含めず、XCTestのUIテストターゲットで実行します。

Debugビルドの起動引数に `-StoryAdventurePreview` を指定すると、確認用のストーリーモードを直接開けます。確認用進行は `story-adventure-debug` のUserDefaultsに保存し、問題は固定の確認用データ、共通コイン・ミッションへの書き込みは無効です。通常のホーム導線を確認する場合は、この起動引数を外します。

開発者モード（Debugビルド）では、通常版・画像版のどちらも全コマを行き先に選んで移動できます。未探索の道やイベントを通過しても、途中の宝箱・モンスターの報酬は取得しません。橋・森の主・港への移動では、セーブの整合性に必要な鍵・橋の開通・森の主のクリア状態を補います。港への移動で森の主をスキップした場合は、そのコイン報酬を付与しません。戦闘中・会話中の移動は引き続き制限します。Releaseビルドでは通常の移動条件を使います。
